# Claim and evidence register

This register belongs to the working paper at release `v0.5.0`. The audited
artifact is identified by the SHA-256 digest of `hayahash.h`, not by a
commit: any commit that leaves the header byte-identical carries every
result here forward. The digest, the commit that introduced that header
(`e5e54840bc2a24c6af796e5d1537fdf0f4f270e7`), and the verification values are
defined once, in `paper/snapshot.tex`; `make -C paper check-snapshot`
verifies that this file, the checkout, and the header agree.

Evidence states:

- **code-derived** - follows directly from the named implementation, or is
  proved in the paper from the specification;
- **reproduced** - rerun from this worktree while preparing the draft;
- **archived** - raw output and method are stored under `paper/results/`;
- **reported** - stated by the project but not independently reproducible
  from the current worktree;
- **open** - evidence is missing; the paper's open-problem list carries it.

## Interface and specification

| Claim | State | Evidence | Update rule |
|---|---|---|---|

## Proved properties

Each row is a statement the paper proves from the specification in Section
"Specification". They are structural statements, not collision-resistance
claims for the complete hash. Recheck every proof if rotation counts,
constants, load rules, block sizes, or buffer constants change.

| Claim | State | Evidence |
|---|---|---|
| The absorb chain `t_i = w_i + rotl(w_{i-1},27)` is a bijection on stripe sequences, and two inputs that first differ at stripe `j` produce absorbed values that first differ at `j`. | code-derived | Lemma "Absorb chain bijectivity" |
| `inj` and `inj2` are bijections; any odd number of rotation terms is, and any even number is not. | code-derived | Lemma "Injection bijectivity" |
| `fmix`, `fmix128`, and `lfmix` are bijections. | code-derived | Lemma "Finalizer bijectivity" |
| Inputs of different lengths that reach the finalizer with equal state produce different digests in both widths. | code-derived | Lemma "Length separation" |
| For a fixed length at most 16 and a fixed seed, the 128-bit digest is injective in the message; at exactly 16 bytes it is a permutation of the 128-bit space. | code-derived | Theorem "Short-input 128-bit injectivity" and its corollary |
| For a fixed length at most 16 and a fixed message, the 128-bit digest is injective in the seed. | code-derived | Corollary "Seed injectivity on the short path" |
| Multiplication by an odd `c` fixes `2^63`; it fixes the four-element subgroup generated by `2^62` pointwise exactly when `c = 1 (mod 4)`, which holds for `K`. | code-derived | Lemma "Top-window invariance" |
| A carry-matched residual displaced by `r` per stripe re-enters the top window after `D(r) = min{d>0 : rd = 0, 1, or -1 (mod 64)}` stripes; `D(21) = 3` and `D(27) = 19`. Same-lane re-entry is further restricted to the subgroup generated by `L*r` mod 64. | code-derived | Lemma "Ladder return distance"; both values verified by direct enumeration in the proof |
| The four-lane loop never exceeds 36 chained stripes; the eight-lane loop injects a raw stripe into lane 0 every 8 stripes; the wall injects the final dangling rotated copy on every path with at least one complete stripe. | code-derived | Proposition "Stripe bounds" |
| A fold rotation `r'` inverts the absorb rotation `r` exactly when `r + r' = 0 (mod 64)`; the finalizer uses 33, not 37. | code-derived | Lemma "Fold-rotation resonance" |
| The streaming interface reproduces both one-shot digests under every split of the input. | code-derived, reproduced | Proposition "Streaming equivalence"; additionally checked by `tests/hash128.c`, rerun for this draft |

## Cost model

| Claim | State | Evidence | Update rule |
|---|---|---|---|
| A block-structured absorb with `L` lanes, `B` bytes per block, one multiply per 8-byte stripe, and longest carried chain `c` sustains at most `min(B/c, 8u)` bytes per cycle. | code-derived | Proposition "Bulk rate bounds" | A first-order model: it ignores load ports, front-end issue width, and reorder-window effects, and predicts which resource binds rather than a rate. |
| At `lambda_add = 1`, `lambda_mul = 3`, `u = 1`, hayahash's bulk loop is issue-bound (`B/c = 12.8` against `8u = 8`) and ChibiHash v2's is latency-bound (`B/c = 6.4`), at identical instruction density of five operations per 8-byte stripe. | code-derived | Dependency graphs read from `hayahash.h` and `tests/chibihash_v2.c`; operation counts stated in the paper | Recount if either bulk loop changes. The comparison is a statement about dependency placement, not a measured speed claim. |

## Open

Each item is carried by the paper's open-problem list and has no evidence in
this register yet.

| Item | Why it is open |
|---|---|
| A bound for the lane recurrence: an almost-universality bound comparable in form to PolymurHash's, or a documented argument that this construction admits none. | The recurrence alternates a GF(2)-linear and a mod-2^64-linear step; no closed form exists in either algebra. |
| A bound on the number of free carry conditions per ladder step. | The ladder-return lemma counts stripes between top-window returns but says nothing about the satisfiability of the carry patterns each step needs. |
| A rerunnable archived differential search over the absorb chain and folds. | The channels in the paper were found by ad-hoc construction, not by a search that can be replayed. |
| Archived raw full-suite SMHasher3 runs for both widths across every compiled dispatch shape. | Only the 128-bit EPYC run is archived. |
| One generated machine-readable vector table consumed by every port. | Each port currently carries its own table. |

## Deliberate exclusions

The paper does not claim cryptographic security, collision resistance against
an adversary, universality, a proof for the complete construction, or any
speed record. It carries no benchmark tables: the only performance statement
it makes is the analytic regime of the cost model above, which is derived
from dependency graphs rather than measured. Measured throughput lives in
`docs/benchmarks.md` and the records under `paper/results/`, and is outside
this register's scope except where a row above cites a record for a
non-speed claim.

The Speed and Hashmap sections inside archived SMHasher3 runs are the tool's
own timings and back no claim in the paper.
